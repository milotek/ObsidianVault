> I couldn't figure out how you generated the header string in your doc  

Milo - [This](http://google3/java/com/google/android/libraries/search/silk/web/core/SilkCapabilitiesHeaderProvider.java;l=129;rcl=901360648) is the driver function on the native client. For each service we support (i.e. the ones added the WebX WebConfig) we append their capabilities, service ID and the platform into a [proto](http://google3/search/frontend/silk/runtime/capabilities_header.proto;l=15;rcl=901360648) which is base64 encoded. Vasanth may have emulated just this, or intercepted a request and pulled the value out of the x-silk-capabilities-header field.  
  
For this to be truly seamless we can delegate to the all_services JSON file I talked about the other day and dynamically form this based on what the user wants to emulate. In the short term we can just reuse an existing header which enables AIM and set that as a dropdown option for instance.
