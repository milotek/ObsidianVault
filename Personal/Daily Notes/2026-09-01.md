## Description
The Silk Client Emulator has two modes, 

On quick enough connections, Silk loads before the extension is finished setting up the client emulator -> the client emulator does not intercept the sub requests in time. We only receive them again after the transport layer's [timeout has passed](http://google3/javascript/search/silk/transport/transport_tng_mod.ts?q=symbol%3A%5CbwaitForHandshake%5Cb%20case%3Ayes) (i.e: if you wait on the page, they will get picked up)

AIM, at some point began, sending out Silk event subscription requests earlier than it used to, so this is now an issue for them in particular.
