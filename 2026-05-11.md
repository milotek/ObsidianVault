```
#!/bin/bash

EDITOR_ID="com.sublimetext.4"

# Basic text types
duti -s $EDITOR_ID public.plain-text all
duti -s $EDITOR_ID public.text all
duti -s $EDITOR_ID public.source-code all

# Markdown
duti -s $EDITOR_ID net.daringfireball.markdown all

# Common file extensions
extensions=("txt" "md" "markdown" "js" "ts" "py" "go" "rs" "c" "cpp" "h" "hpp" "css" "html" "json" "yaml" "yml" "xml" "sh" "zsh" "bash")

for ext in "${extensions[@]}"; do
    duti -s $EDITOR_ID $ext all
done

echo "Default editor associations updated!"
```

### **[Silk Web Inspector] Display list of mocked methods and events to the user**

Add a table or dynamic list inside the Emulator DOM to read and render every item inside `silkMocks`. Include a "Delete" button attached to each row that invokes removal logic against the datastore keyed by service/method.

### **[Silk Web Inspector] Persist Silk mocks in WebDevX/Chrome extension storage**

Connect the `silkMocks` datastore to Chrome extension storage serialization. Rather than blowing rules away when the developer refreshes the tab or opens/closes the DevTools panel, dump and reconstitute rules to/from `chrome.storage.local`. This addresses the design doc's desire to save dev time manually re-typing base64 blob entries.
